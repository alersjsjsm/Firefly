# 折腾一晚上，博客终于上线了

今天终于把博客搭起来了。

过程比我想象的难。我以为"用现成模板"就是把文件下载下来、改个名字的事，结果从装环境到推送上线，一路踩坑，每个坑都卡了我一阵。

把过程记下来，一是给自己留个复盘，二是如果有人在同样的地方卡住，也许能少走点弯路。

## 第一个坎：环境

第一步装环境就卡住了。

Node.js、pnpm、Git 三个东西，我原本以为装完就完事，结果装完发现命令根本跑不了——报错说"禁止运行脚本"。

查了半天才知道是 PowerShell 的执行策略问题。Windows 默认不允许运行 `.ps1` 脚本，而 `npm`、`pnpm` 这些命令本身就是一个 `.ps1` 包装脚本，所以全被挡住了。

解决办法是给当前用户设置执行策略：

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

改完之后要**重新开一个终端**才生效——这一步我一开始不知道，改完发现还是不行，又折腾了一会儿。

## 第二个坎：装依赖

克隆下来之后装依赖，第一次直接失败了。

我用的模板依赖很多，一千多个包。默认从 npm 官方源下载，在国内速度很不稳定，跑到一半超时中断了。

改成国内镜像之后好很多：

```powershell
pnpm config set registry https://registry.npmmirror.com
```

改完 7 分多钟装完。第一次那一版跑了 4 分钟还是失败了，白等。

**这个教训很实在**：国内做前端开发，第一件事就是换镜像源，别硬扛。

## 第三个坎：字体加载失败，服务起不来

依赖装完了，`pnpm dev` 启动，结果直接报错退出：

```
[CannotFetchFontFile] An error occurred while fetching the font file from
https://cdn.jsdelivr.net/fontsource/fonts/zen-maru-gothic@latest/...
```

模板用了几种网络字体，这些字体要从 `cdn.jsdelivr.net` 下载，而这个域名在国内基本连不上。

我的解决方式是改字体配置，把引用了那几个远程字体的地方留空，回退到系统字体：

```ts
bannerTitleFont: "",      // 原来是 "--font-zen-maru-gothic"
bannerSubtitleFont: "",   // 原来是 "--font-inter"
codeFont: "",             // 原来是 "--font-jetbrains-mono"
```

改完服务就能起来了。

**顺带一个感受**：中文字体文件动辄几 MB 到十几 MB，为了几个字的风格付这个加载成本其实不太值。用系统自带的中文字体（微软雅黑、苹方），用户看到的反而更顺眼，打开也更快。

## 第四个坎：推送代码

代码写好了要推送到 GitHub，结果 `git push` 一直失败：

```
Failed to connect to github.com:443 after 21090 ms
```

开了代理还是不行，报 TLS 握手失败：

```
schannel: failed to receive handshake, SSL/TLS connection failed
```

最后发现是我代理软件的问题：它开了两个端口，**7890 能建立连接但 TLS 一定失败，7891 才正常**。把 Git 的代理指到 7891 就好了：

```powershell
git config --global http.proxy http://127.0.0.1:7891
git config --global https.proxy http://127.0.0.1:7891
```

配完 `git push` 十几秒就完成了。之前那个端口白等了二十多分钟。

**这个坑很隐蔽**：7890 端口看起来是通的（连接能建立、返回 200），但实际传数据就断。如果只看"能不能连上"，会误以为没问题。

## 最后一个坎：内容

这个是我不太想面对的部分。

用的模板自带一整套示例内容——作者写的介绍文章、Markdown 教程、示例项目、示例相册、演示动态。看起来很完整，但**没有一个是我的**。

如果直接改个名就发布，首页置顶的是别人的文章，项目页挂的是别人的项目，还把别人的作品当成自己的作品集，这就不是"参考模板"，是拿别人的东西充数了。

所以我把这些都删了——大概删了三千多行：

- 13 篇示例文章
- 3 篇模板使用指南
- 18 张示例配图
- 2 个示例项目
- 4 条演示动态
- 模板相册、示例音乐、示例公告

删完网站变得很空：一篇文章、一个关于页、零个项目。

但我觉得这样是对的。**空着至少是真的。**

## 现在的样子

现在的博客很简单：一篇关于页、一篇开篇、皮肤调成了橘黄，背景和头像换成自己喜欢的图。

项目页还空着，因为我现在确实没有能拿出手的项目。

这可能是最需要补的一块。之后做的事我会陆续整理进来——哪怕是很小的东西，只要是真的做过，就比挂三个假项目强。

## 一些想法

折腾这一晚上，最大的收获不是"我有个博客了"，而是几个具体的东西：

**第一，报错信息真的能告诉你原因。** 我一开始看到 `CannotFetchFontFile` 一头雾水，但它明确写了是 `cdn.jsdelivr.net` 下载失败，顺着查就解决了。后来 TLS 那次，`schannel` 这个词也直接指向了 Windows 的 TLS 实现，不是网络不通。

**第二，网上教程的"默认情况"不一定适用你。** 大部分教程假设你装的是标准版本、用默认端口、在国内或者国外。但你的实际情况可能是 Node 装在 E 盘、代理开了两个端口、PowerShell 策略被改过。遇到不符合的地方，得按自己的实际情况调，别死磕教程。

**第三，早换镜像源、早配代理。** 这两个是纯粹的时间浪费，越早处理越好。

**第四，用模板不丢人，抄内容才丢人。** 开源模板本来就是给人用的，许可证写得明明白白可以用。但模板是框架，内容得是自己的。
